Yesterday's canary study has consequences already: one provider has owned up, and a router has started pulling endpoints. The rest of the day is quieter, mostly about where state lives in an inference stack.

## 🔥 OpenRouter drops three providers over leaked prompts
Together AI posted on 21 November that an AI coding agent committed a credential to a public repository, opening a private Hugging Face repo of stored prompt samples from June and July 2026. An unauthorized party downloaded them. A day later OpenRouter said it had off-boarded three providers, pulled 125 endpoints from its Zero Data Retention (ZDR) list and notified customers.

The design point: a ZDR flag is a promise by whoever sits at the end of the chain. OpenRouter says it is adapting the researchers' testing approach to run such checks on an ongoing basis; until then, treat the flag as a claim to test.

**Affected:** Together serverless inference prompts from June and July 2026 (MiniMax M3, GLM-5.2, Kimi K2.6) · **Fixed in:** not applicable, hosted service · **Severity:** not stated · **Stopgap:** enable ZDR in account settings · **If compromised:** affected customers are contacted directly; security@together.ai

[Source](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/) · [Together's notice](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026)

## 🚀 GPT-Live-1.1: better multilingual voice, and a cheap standby rate
OpenAI released GPT-Live-1.1 on 19 November. It listens while it speaks and handles accent and pronunciation more consistently across languages. The model page lists $0.05 a minute active and $0.02 standby, where standby applies to WebRTC sessions while inference is paused. Backend model and tool use are billed separately.

Standby isn't new, though: the changelog says it's configurable for GPT-Live-1 as well, so the upgrade is quality, not price. It also lives on its own endpoint, `v1/live/sessions`; Realtime, Responses and Chat Completions aren't supported.

**Try this:** replay a week of real call logs with your silence patterns against your current voice stack, and compare cost per resolved call and time to first word after standby.

[Source](https://developers.openai.com/api/docs/models/gpt-live-1.1) · [Changelog](https://developers.openai.com/api/docs/changelog)

## 🤖 The Copilot harness is now the VS Code default
VS Code announced on 18 November that the Copilot harness, built on the Copilot SDK, is the default for new agent sessions. The older Local harness is deprecated and goes in February 2027, unless your organization restricts it. In one Business/Enterprise rollout the default group used 14.2% fewer tokens per active device, at 9.6% lower estimated processing cost. These are Microsoft's numbers.

If your team's tooling or habits depend on the Local harness, you have about three months. The bigger shift is that the editor, CLI and cloud agents now share one runtime, so a fix lands everywhere at once, and so does a regression.

[Source](https://code.visualstudio.com/blogs/2026/11/18/copilot-harness)

## ✍️ Graham Dumpleton builds a Rust server with AI, in the open
Simon Willison flagged Muru on 21 November: Dumpleton, who started mod_wsgi, is building an AI-assisted Rust server for WSGI and ASGI apps and has written 18 posts about it since 4 November. He says the AI may be doing a lot of the work on the surface, but deciding what isn't good enough yet is still down to him. The project is Apache-2.0 and alpha, with 0.1.0 pre-releases on PyPI.

The useful part for architects is the method: writing up each design decision exposes the weak spots before the code does. His feedback rule is a good one for any AI-written project too: don't send a patch, describe the problem.

[Source](https://simonwillison.net/2026/Nov/21/muru/) · [Muru on GitHub](https://github.com/muruhq/muru)

## 🏗️ Valkey 9.2 adds a shared KV cache for GPU fleets
Valkey 9.2 went GA with a distributed KV caching capability, announced by the Linux Foundation on 19 November. It's a shared cache across a GPU fleet, built on LMCache and wired to vLLM and SGLang with a config change. The release claims up to 40% lower inference cost and up to 80% lower time to first token. Multiverse Computing, quoted in it, reports 50% more requests on the same GPUs.

Moving KV state off the GPU node makes prefix reuse a fleet-wide property rather than a per-replica one. The price is a network hop, so hit rate and fetch latency against recompute time decide whether it pays.

**Try this:** replay a day of multi-turn traffic through vLLM with and without the Valkey tier, and compare p95 TTFT and GPU-hours per 1,000 requests.

[Source](https://www.linuxfoundation.org/press/valkey-9.2-lowers-cost-of-ai-workloads-on-existing-infrastructure-alongside-new-distributed-kv-caching-capability)
