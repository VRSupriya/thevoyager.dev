Two of today's stories are about things you probably set once and forgot: a vendor's API key and a sampling parameter. Neither is glamorous, and both can bite on a Monday.

## 🔥 PingCAP's breach put encrypted TiDB Cloud API keys in an attacker's hands
PingCAP says someone used stolen service-account credentials to get into internal systems between 9 September and 7 October, and copied source code, billing records, SQL editor text and encrypted TiDB Cloud API-key values. The company says it found no evidence that data stored in TiDB was affected, and it hasn't yet said which customers are involved. The attacker's own claim of 10.6 TB is unverified.

If you run agent memory or a vector store on TiDB Cloud, don't wait for the customer list. PingCAP's guidance is to create replacement management keys, update and test what depends on them, then revoke the old ones. Your SQL editor history is also in scope, so check it for pasted secrets.

[Source](https://www.pingcap.com/trust-hub/security/security-update-october-2026/) · [Customer actions](https://www.pingcap.com/trust-hub/security/customer-actions-october-2026/) · [InfoQ](https://www.infoq.com/news/2026/10/pingcap-cloud-data-breach/)

## 🚀 Claude's new API version returns a 400 if you send temperature
Anthropic's API version `2026-10-21` rejects `temperature`, `top_p` and `top_k` with a 400 error, even at default values. It also rejects documents placed in assistant messages and citations on user text blocks. The SDKs that default to the new version send it automatically, so an upgrade can break a working service. Bedrock gets the new version only for Claude 4.7 and later.

The quiet cost is on older models such as Sonnet 4.6, where a lowered temperature was doing real work for consistency. You can pin `2023-06-01` for those calls, but that's a stopgap: move the consistency into the prompt and an eval.

**Try this:** grep for the three parameters, run 50 representative prompts with and without them, and compare pass rate. If it drops more than a couple of points, keep that call on the old version.

[Source](https://platform.claude.com/docs/en/api/migration-2026-10-21) · [Deprecations page](https://platform.claude.com/docs/en/about-claude/model-deprecations)

## 🤖 Bayer's agent platform runs 22 specialist agents, and most of the savings are plumbing
Bayer Crop Science describes, in an AWS post, an agentic decision engine on Bedrock AgentCore with a LangGraph supervisor routing to 22 domain-scoped agents. It resolves about 80 percent of user questions without an engineer in the loop in its first phase, and a diagnosis that took over an hour now takes under 10 minutes.

The numbers worth stealing are the dull ones. Exposing APIs through AgentCore Gateway as MCP tools cut per-API integration overhead by over 99 percent, and caching the stable prompt prefix cut input-token cost by 20 to 30 percent. It's a vendor-published case study, and the rollout is still to a gated group of 100-odd users, so treat the 80 percent as an early figure.

[Source](https://aws.amazon.com/blogs/machine-learning/how-bayer-crop-science-built-an-agentic-decision-engine-on-amazon-bedrock-agentcore-with-aws-unified-operations/)

## 🔬 A ten-year-old CNN beat two frontier LLMs at reading skin lesions
A dermatologist tested GPT-6 Astra and Claude Fable 5.1 on 200 biopsy-proven lesions from the public MILK10k set. Each LLM picked the right first diagnosis for 42 percent, against 62 percent for an Inception v3 fine-tuned on 68,011 archive images. The cases, prompts, replies and scoring code are published.

The honest reading: small data (30 melanomas), each LLM run once, and the CNN at its preset threshold discharged 18 of 30 melanomas, a serious miss of its own. It's a nudge to benchmark a small specialised model before reaching for a frontier API on a narrow task, not a verdict.

[Source](https://lynchlab.net/llm-skin-cancer)
