Most of today's news comes down to who holds your keys and how much of an agent's work you can see. Start with the first one.

## 🔥 Northflank's breach put customers' AI API keys to work for someone else
Northflank disclosed a security incident on 30 October and told customers to rotate all user-defined credentials. Its status page says to assume all environment variables were decrypted, and later reports unauthorised use of AI API keys supplied to the platform. Neither the cause nor the number of customers hit has been published.

If model keys sit in a hosted platform's environment variables, that platform is part of your key management. Rotate at the provider, and check billing logs for calls you didn't make.

**Affected:** any Northflank customer's secrets: environment variables in workloads, secret groups, global secrets and add-on credentials · **Fixed in:** not applicable (hosted service); Northflank has added secret rotation for several add-ons and audit logs for all accounts · **Severity:** no formal rating; the status page lists it as a major outage · **Stopgap:** rotate all user-defined credentials, disable public access on add-ons, revoke and replace AI keys at the issuing providers · **If compromised:** review provider usage and billing logs, and report suspicious activity to Northflank and the provider
[Source](https://status.northflank.com/cmvv0rn5a092f14rutwccodpp) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/northflank-security-breach-leads-to-abuse-of-customers-ai-api-keys/)

## 🚀 Microsoft's 4B Mage-VL-Cowork drives desktops and shells with one policy
Microsoft put Mage-VL-Cowork on Hugging Face this week under Apache-2.0. It's a 4B vision-language agent that handles both GUI control and shell or Python from a single policy, built on a Qwen3-4B-Instruct-2507 backbone.

The model card reports 66.0% on OSWorld-Verified (two-run average, 361 tasks, 50-step budget) and calls that the highest among 4B models. A 9B model, ScaleCUA-Qwen3.5-9B, scores 68.7%. Those are Microsoft's numbers. For design, a model this small can run next to the app it controls, which changes the latency and data-residency conversation for desktop automation.

**Try this:** run it on 20 of your own GUI-plus-shell tasks against your current computer-use model, and compare completion rate and cost per completed task.
[Source](https://huggingface.co/microsoft/Mage-VL-Cowork) · [Commit history](https://huggingface.co/microsoft/Mage-VL-Cowork/commits/main)

## 🤖 Factory's Droid 1.0 lets the model script its own tool calls
Factory published Droid 1.0 on 29 October, a model-independent coding-agent harness that ships as a desktop app, a terminal UI and a TypeScript SDK. Its Script Mode has the model write JavaScript that runs in a sandbox with no file, network or system access of its own; Factory says that cuts cost 15% versus direct tool calls on Claude Opus 5.5.

On Factory's own Terminal-Bench 4 runs with GPT-6.1 Sol, Droid scores 57.6% at $0.79 per passed task, against 54.0% for Codex and 51.0% for OpenCode, and Factory says it's about 10% slower than Codex there. The architectural point is that the harness, not the model, is where cost gets decided, and a harness you can swap models under is a hedge against vendor lock-in.

**Try this:** take your most tool-heavy agent flow and compare direct tool calls with a scripted version. Metric: cost per passed task at the same pass rate.
[Source](https://factory.com/news/frontier-harness)

## 🔬 A NeurIPS paper says final-score agent evals hide where agents break
"Prefix Executability" (arXiv 2610.40444, 29 October, accepted to NeurIPS 2026) evaluates tool-using agents on the steps they execute, not only on whether the final task succeeds. It runs on BFCL-v3 multi-turn, ToolSandbox and the Airline and Retail splits of τ³-bench.

Its main claim is that outcome-only and prefix-level rankings diverge, so two agents with the same pass rate can fail in different places. The abstract gives no numbers, so treat it as an argument to test on your own traces. If your eval dashboard shows only pass rate, log which step first became unexecutable and see whether your ranking of agents changes.
[Source](https://arxiv.org/abs/2610.40444)

## ✍️ Latent Space: a finance agent that runs for ten days and keeps a memory per client
In a 26-minute Latent Space episode, an Arca executive describes agents doing long-horizon financial work where tasks can take "ten days" and the work is "very stop-start". The system keeps persistent state for every client, and a custom harness picks the best model per task from internal benchmarks, with Claude as the primary provider.

The useful part is the ownership argument: because the harness is theirs, Arca can change model providers if needed. Agents propose, and human advisors handle trading and money movement. If your agent work spans days, design the state store and the human hand-off first, and treat the model as the replaceable piece.
[Source](https://latent.space/p/arca/)

## 🏗️ Databricks makes real-time mode GA for Spark Declarative Pipelines
Databricks announced on 29 October that Real-Time Mode is generally available for Spark Declarative Pipelines. Its benchmarks on customer feature-computation workloads say up to 92% faster than specialized engines like Flink, and a Feature Store path with 200 ms end-to-end p99 latency from Kafka to the online feature store.

For AI systems this is the feature-freshness layer: fraud, personalisation and agent context that go stale in a micro-batch. It needs the pipeline in continuous mode with `spark.databricks.streaming.realTimeMode.enabled` set to `true` and the `RealTime` trigger. All the numbers are Databricks's own, so replay one production stream before you move anything.
[Source](https://www.databricks.com/blog/announcing-general-availability-real-time-mode-spark-declarative-pipelines-databricks)
