Most of today is about limits: what an agent is allowed to do, how fast it can do it, and what a model can prove about itself. Start with the one that moved furthest in a day.

## 🔥 OpenAI built a pipeline that found 948 Linux kernel privilege-escalation bugs
OpenAI's news feed says it built an autonomous pipeline that found, validated and generated patches for 948 local privilege-escalation vulnerabilities in the Linux kernel. The post is filed under Security and dated 4 November. OpenAI's article page wouldn't load for us, so this rests on the feed text; the patches, CVE list and affected versions aren't in it.

If the claim holds, the cost of finding kernel root bugs just dropped for defenders and attackers alike. Plan for a bigger stream of kernel fixes, and ask whether your patch window can absorb it.
[Source](https://openai.com/index/a-thousand-fewer-paths-to-root) · [OpenAI news feed](https://openai.com/news/rss.xml)

## 🚀 Ripple-65B-Preview is an Apache 2.0 dense coding model you can run yourself
Ricursive Intelligence published Ripple-65B-Preview on 4 November: a dense 65B-parameter transformer, not a mixture of experts, with BF16 weights on Hugging Face under Apache 2.0. The company's own numbers put it at 80.52 on Terminal-Bench 2.1, which it calls the best US open-weight score; those are vendor results and the authors say they vary with the harness. GMICloud lists it on OpenRouter at $0.20 per million input tokens and $0.60 per million output.

Dense means every token pays for all 65B parameters, but it also means simple serving and predictable latency. Worth a test against your current coding agent on your own repos.

**Try this:** run 20 of your real tickets through Ripple and your current model on the same harness. Compare resolved tickets per dollar.
[Source](https://www.ricursive.com/ripple) · [Model card](https://huggingface.co/ricursiveAI/Ripple-65B-Preview) · [OpenRouter](https://openrouter.ai/ricursiveai/ripple-65b-preview)

## 🤖 Inkitt's PR agent keeps the trust boundary in the orchestrator, not the model
InfoQ describes how Inkitt built an internal agent that turns a Slack message, a Linear ticket or another agent's API call into a pull request. An event-driven orchestrator coordinates short-lived containers instead of a fixed pipeline. Those containers hold only short-lived repo and model credentials, with no access to Slack or Linear credentials, cloud identities or arbitrary network connections.

Tasks touching database migrations, schemas, CI, auth or payments are rejected up front. The agent opens draft PRs only and can't bypass branch protection. Verification, CI repair and merge-conflict resolution get two attempts each. The point to copy: the rules live outside the model, so a confused agent hits a wall instead of a judgment call.
[Source](https://www.infoq.com/news/2026/11/inkitt-one-shot-pr-creator-agent/)

## 🔬 Context rot looks like a fight for attention, not a length problem
A preprint tested five open models of 0.5B to 3B parameters. Neutral filler up to 32K tokens cost almost nothing: Qwen2.5-1.5B stayed at 0.96 to 1.00 accuracy. Competing statements dropped the same model to 0.11 to 0.21 at 8K to 32K. Across 126,473 trials, attention on the evidence explained 35 to 58% of the loss variance and log length explained 2 to 8%.

The authors say it's correlational, one synthetic task, and models of 3B or less. Still, it suggests retrieval should prune near-duplicate and conflicting passages, not just cap length. The authors release the probe and trial-level data on GitHub.
[Source](https://huggingface.co/papers/2611.04169) · [The paper](https://arxiv.org/abs/2611.04169) · [Code and data](https://github.com/yliusci/length-is-cheap)

## ✍️ Import AI 479: on live tasks, the clock beats the model
Jack Clark's issue 479 leads with Realtime-Bench: 50 interactive tasks, 30 web and 20 game. On the wall-clock setting the best model, GPT-6 Astra at high reasoning, passed 36%. With the clock paused, high-reasoning models reached around 70%, up to 80%.

For an architect that's a latency budget problem before it's a model problem. If your agent drives a UI, a call, or anything that moves while it thinks, measure it with the clock running. The same issue covers a DIA space-security report and DeepMind's Genie 4 preview.
[Source](https://importai.substack.com/p/import-ai-479-spacewar-low-latency)

## 🏗️ Anthropic's FlashProve shows what it costs to prove which model answered
Anthropic's Frontier Red Team released FlashProve on 2 November, an Apache 2.0 prototype that uses zkSNARKs so a user can check a response came from a committed model without seeing its weights. On Llama 4 Maverick it proves about 110 tokens per second on one H100, at about 72 times the per-GPU time of vLLM serving the same batch of 24 requests, with about 19 MB per 1,024-token request. Verification takes about 17 seconds on 24 CPU threads.

Anthropic calls it intermediate progress: integer weights, greedy decoding and contexts up to 1,024 tokens. It's not deployable, but it puts a concrete price tag on auditing a third-party inference provider.
[Source](https://www.anthropic.com/research/provable-inference) · [Code](https://github.com/anthropics/FlashProve)
