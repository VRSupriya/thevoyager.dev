Friday brings one bug that's already being exploited and a few that aren't yet. Start with the first.

## 🔥 CISA says a LiteLLM guardrail bug is being exploited. Block the endpoint today.
CISA added CVE-2026-40217 to its Known Exploited Vulnerabilities catalog on 18 November, with a due date of 2 December for federal agencies. It's a sandbox escape: CISA describes code execution through bytecode rewriting at `/guardrails/test_custom_code`. LiteLLM's own advisory dates from May and rates it Moderate, so a team triaging by score alone has probably parked it.

A gateway holds your model-provider keys, so code execution there is a credential problem. Let exploitation status outrank the CVSS number.

**Affected:** LiteLLM >= 1.81.8 and < 1.83.10 · **Fixed in:** 1.83.11 (the advisory's Patches section; its header lists 1.83.10 or later) · **Severity:** Moderate, CVSS v4 5.9 in the advisory; in CISA KEV since 2026-11-18 · **Stopgap:** block POST /guardrails/test_custom_code at your reverse proxy or API gateway · **If compromised:** not stated in the advisory

[Source](https://github.com/BerriAI/litellm/security/advisories/GHSA-wxxx-gvqv-xp7p) · [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

## 🚀 SenseNova-Loop-9B gets more out of its weights by running some layers twice
SenseNova-Loop-9B had its official release on 17 November (a preview came on 31 October), under Apache-2.0. It has about 9B parameters but runs layers 4 to 27 twice as a shared looped block, which the card puts at about 14.6B inference-equivalent. It takes text and images, has a 512K context, and the card reports NL2Repo at 41.36 against 44.60 for Qwen3.8-27B.

So you pay 9B in weight memory and get something near a mid-size model's compute. Whether that wins for you depends on your serving stack: the card says vLLM and SGLang support sits in unmerged pull requests, and the repo is gated behind accepting its conditions.

**Try this:** run it on 20 of your own repo-level coding tasks against your current ~27B model. Compare pass rate and GPU memory at the same context length.

[Source](https://huggingface.co/sensenova/SenseNova-Loop-9B)

## 🤖 AWS lets agents pay Marketplace sellers per request, on your AWS bill
On 19 November AWS said agents can buy select AWS Marketplace products per request in US dollars, using the x402 protocol through Bedrock AgentCore payments. Charges land on the existing AWS bill, so there's no crypto wallet to manage. Sellers integrate an x402 SDK; buyers enable a Marketplace payment connector and find listings through AgentCore Gateway.

The part worth reading closely is the control surface. You set spending limits, approved sellers and guardrails before an agent transacts, and transactions show up in CloudTrail and Cost Explorer. That's the shape to copy: treat an agent's budget like an IAM boundary, decided up front and audited afterwards. The announcement doesn't list fees or which products qualify.

[Source](https://aws.amazon.com/about-aws/whats-new/2026/11/marketplace-agentic-payments-agentcore/)

## 🔬 A 4B "fast thinker" decides when your agent needs the big model
A preprint from USTC and NTU trains a 4B model (LoRA on Qwen3.5-4B-Base) as a System-1 for agent workflows, with a confidence gate that hands hard steps to the large model. With DeepSeek-V4.1-Flash as the large model, the authors report 86–91% of episode cost saved (89% on average) at +0.5 points of task performance across SOPBench, ALFWorld and WebShop. System-1 scores a decision in 21.8–31.7 ms, against 1.51–1.78 s for System-2.

The gate is the whole trick: without it, ALFWorld success falls from 96.3% to 40.3%. If you build agents, the lesson is that routing quality matters more than the small model, so measure how well your confidence signal separates easy steps from hard ones. These are the authors' own results, and one ablation uses a single seed.

**Try this:** log 200 decision points from one production agent, route them with a small model plus a confidence threshold, and compare cost per success against all-large.

[Source](https://huggingface.co/papers/2611.23751) · [The paper](https://arxiv.org/abs/2611.23751)

## ✍️ LangSmith Tool Gateway puts agent tool identity behind one URL
LangChain put Tool Gateway into public beta on 19 November. It routes an agent's tool calls through a single URL that handles identity, access and logging, and works with any MCP client. Six servers come with built-in OAuth (Google, Microsoft, Salesforce, GitHub, Linear, LinkedIn), seven more use an API key or are public, and calls can run as the user or as the agent. The audit log is on Enterprise plans.

It's the gateway pattern applied to tools: credentials and policy leave the agent code and live in one place. The price is another hop in the path and a place where permissions live that you don't operate. Decide which side of that trade you want before the agents multiply.

[Source](https://www.langchain.com/blog/langsmith-tool-gateway)

## 🏗️ Booking.com dropped 92% of its Hadoop workflows instead of migrating them
In a QCon London talk on an InfoQ page dated 18 November, Principal Engineer Jabez Eliezer Manuel described Booking.com's ML and data platform. Hadoop had about 190,000 tables and 7,000+ workflows; 92% of the workflows failed a business-criticality test and were dropped rather than migrated. Serving covers 480-plus models and about 400 billion predictions a day at under 20 ms average latency.

The migration lesson travels well: asking which pipelines still earn their keep was cheaper than moving all of them. The talk also puts experiment success at just under 25% across 150,000 or more experiments, which is a useful base rate for anyone budgeting AI POCs. It's the company's own account, told as a talk.

[Source](https://www.infoq.com/presentations/bookingcom-ml-data-platform-evolution/)
