Where does your agent keep its keys? Three of today's items are that question in different clothes, and the first one is the sharpest.

## 🔥 Botpress says an attacker read bot configurations in 16 customer workspaces
Botpress disclosed on 6 November that an unauthorized party used an employee API credential, between 13 and 21 October, to read bot configurations in 16 customer workspaces and change integration settings in 2 others. The goal was resellable AI usage, and there was no ransom demand.

A bot configuration can include AI provider API keys, messaging channel tokens and CRM credentials, says Botpress. If your agent platform is also your secret store, a vendor breach reaches every system those keys open. Botpress says it found no evidence that source code, build pipelines, published packages or end-user conversations were affected.

**Try this:** list every third-party key stored in your bot or agent platform settings (baseline: the count today), then measure how many could be scoped to one bot or moved behind a gateway you control.

**Affected:** Botpress cloud, 16 workspaces read and 2 changed; not a versioned product · **Fixed in:** authentication flaw fixed and credential revoked on 21 October · **Severity:** not stated · **Stopgap:** not stated · **If compromised:** treat every credential stored in the affected bots as exposed and rotate it

[Source](https://botpress.com/blog/security-incident-disclosure-november-2026)

## 🚀 Inkling 2 Small: a 594B MoE with closed weights today and Apache 2.0 promised
Thinking Machines announced Inkling 2 Small on 5 November: 594B total and 17B active parameters, image input, available now on its Tinker service. Weights are closed for the moment. The company says full Apache 2.0 weights follow the next week, after external safety testing.

The headline numbers are the vendor's own, against Muse Spark Open: 30.6 on the Artificial Analysis index versus 24.9, and 72.1% on DeepSWE v1.1 versus 60.0%. It trails on AA-Omniscience, 16.1 versus 25.8, so don't assume it knows more just because it codes better. The first pretraining stage covered 8.4T tokens in 68 hours on GB300 NVL72 racks. Wait for the weights before you plan hosting.

[Source](https://thinkingmachines.ai/news/inkling-2-small/)

## 🤖 AWS shows how to run Claude Code as a remote agent, one microVM per task
An AWS sample, aws-samples/sample-remote-coding-agent, runs Claude Code on Amazon Bedrock AgentCore. Each task gets its own AgentCore runtime session, a microVM, and ends as a GitHub pull request; the agent never merges. The GitHub token comes from AgentCore Identity and expires after 8 hours, and the runtimes sit in private subnets with outbound traffic limited to HTTPS, and the post suggests a firewall allowlist of GitHub and package registries for production.

The useful part is the honesty about limits: Bedrock Guardrails screen the prompt before queueing but don't cover prompt injection that arrives through repo files or command output. AWS pitches it for trusted repos and scoped tasks, not untrusted code. It's a sample, not a product, and takes 15–25 minutes to deploy.

[Source](https://aws.amazon.com/blogs/machine-learning/extend-claude-code-to-remote-sessions-on-amazon-bedrock-agentcore-with-security-controls/)

## 🔬 METR estimates AI research at Anthropic runs about 2x faster
METR published an independent assessment on 5 November: Anthropic's AI R&D pace is about 2x its March 2024 to October 2025 rate (range 1.3–3x), with about 80% of the gain attributed to AI. Staff self-reports of uplift are around 12x, which METR calls very loose evidence.

METR also says Anthropic redacted most of the most informative evidence and dropped compute-allocation verification from the scope, so treat the number as an estimate, not a measurement. If it holds, model releases keep arriving faster: keep an eval suite that lets you swap models in a day, not a quarter.

[Source](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/)

## ✍️ LangChain on async subagents, and what "interrupt" costs you
LangChain's Sydney Runkle and Thushanth Bengre wrote on 5 November that agents need an orchestrator that stays available to the user while subagents run in the background, because a plain ReAct loop blocks on long tool calls. Their `update_strategy` setting controls mid-run steering, and the default, `"interrupt"`, stops the current run and restarts the subagent with the new instruction. Task notifications are in beta, so the API may change.

If you adopt this, a restart means partial work is thrown away: make subagent tasks checkpointed or idempotent first.

[Source](https://www.langchain.com/blog/agents-are-going-async)

## 🏗️ Edera's answer to leaky keys: never give the agent a credential
Edera's 5 November post states the principle bluntly: "Don't give the agent a credential and ask it to behave." Instead the agent holds a narrow capability, such as `github.write(repository="acme/payments")`, enforced by a microVM isolation boundary, with components named capcurl, capsudo and SPIFFE/SPIRE workload identity.

Status is murky. InfoQ says scoped command execution and workload identity have shipped and credential-brokered API access is still to come; Edera's own post calls capcurl a concept. The licence isn't confirmed either. Treat it as a design to borrow, not a product to deploy.

[Source](https://edera.dev/stories/ocap-bounded-authority) · [InfoQ](https://www.infoq.com/news/2026/11/ai-credentials-isolation/)
