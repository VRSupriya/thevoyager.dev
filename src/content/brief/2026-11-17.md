A patch used to give defenders a head start. Today's top story is about attackers who now treat it as the starting gun.

## 🔥 Google says attackers now run AI agents that turn patches into exploits
Google's threat intelligence group (GTIG) reported on 16 November that it found an exposed staging server running `exploit_agent`, a multi-agent framework that diffs popular web software before and after each patch, drafts exploits and runs them with no human involved. GTIG calls it the first time it has seen LLM frameworks automate vulnerability discovery and exploitation end to end.

```stats
8 → 11 | zero-day exploits a month, 2025 average vs 2026 (GTIG)
22 | zero-day exploits in August 2026 alone
```

My read: the days between a patch and its exploit are the part of your risk budget that's shrinking fastest. GTIG describes attackers creating unauthorized service accounts, a botnet making millions of LLM API calls in about 24 hours, and a group editing `.claude/settings.json` to pull down a backdoor. Watching for those is my inference, not GTIG's advice.

[Source](https://cloud.google.com/blog/topics/threat-intelligence/agentic-threat-activity-crosses-a-significant-threshold/)

## 🚀 Alibaba's Qwen4 Max is a 2.4T-parameter model with a 1M-token window
Alibaba announced Qwen4 Max on 16 November. It's a sparse mixture of experts with 2.4 trillion parameters in total and 71 billion active per token, a one-million-token context window and native vision. Alibaba's own Work360 benchmark has it using 35% fewer tokens than Qwen3.8 Max at high reasoning effort. OpenRouter lists Alibaba Cloud at $1.425 per million input tokens and $4.275 per million output tokens. The announcement promises open weights only for smaller Qwen4 models.

That makes this an API decision, not a self-hosting one, so the price per resolved task matters more than the token price.

**Try this:** run 20 of your own hard agent tasks on Qwen4 Max and on your current model, same prompts. Measure cost per resolved task.

[Source](https://www.alibabacloud.com/en/press-room/alibaba-unveils-qwen4-max) · [OpenRouter listing](https://openrouter.ai/qwen/qwen4-max)

## 🤖 A Claude Code VS Code prompt can hide where a symlink really points
A researcher's write-up, published on 11 November, shows that a symlink inside a workspace (their example is `./helpdocs`) can point outside it, while the extension's approval prompt shows only the workspace-looking path. The write-up says the CLI shows the real location and the extension doesn't, and that Anthropic closed the HackerOne report as informative.
If a repo can bring its own symlinks through a git sync, "approve this read" can mean your SSH keys. Treat the prompt as a hint, not a boundary.

**Affected:** extension 2.1.322, which the write-up calls the latest at publication · **Fixed in:** no fix as of the write-up, which calls 2.1.322 unpatched · **Severity:** not stated · **Stopgap:** run `realpath` on the path in the prompt before approving (the write-up's advice); checking synced repos for unexpected symlinks is my addition · **If compromised:** not stated in the write-up

[Source](https://ultrastrike.io/2026/11/claude-code-vscode-plugin-workspace-escape-via-misleading-permission-prompt/)

## 🔬 More agents rarely beat a matched baseline
A preprint, submitted on 13 November, pulls together nine evaluations covering 516 unique multi-agent configurations. Against baselines given the same samples or the same budget, the multi-agent systems average 0.042 lower accuracy, and match or fall below the baseline in 74% of comparable cases. The author's reading is that communication adds nothing when agents share the same evidence; gains need split evidence, external verification or varied models. The paper links its code on GitHub.

Before you add a second agent, give the single agent the same token budget and see which wins.

[Source](https://arxiv.org/abs/2611.17610) · [Code](https://github.com/mahmoudsajjadi/pace)

## ✍️ Nathan Lambert: open models without Jensen Huang
Nvidia announced on 12 November that Huang resigned as CEO and board member, effective immediately. Lambert's post, from 14 November, calls it a major setback for the US open-model ecosystem, says open models were one of Huang's more ambitious bets, and expects Nvidia's funding to dry up. He thinks open-weight inference stays pricey while compute is scarce, and that enterprise post-training is the promising lane. He calls Thinking Machines' Inkling 2 Small the best Western open-weight model "in a while" but far behind Kimi K3.1 Pro.

For planning: don't assume the open-weight price cuts keep arriving at last year's pace.

[Source](https://www.interconnects.ai/p/open-source-ai-without-jensen) · [Nvidia announcement](https://www.sec.gov/Archives/edgar/data/0001045810/000104581026000082/nvidiaannouncesceotransiti.htm)

## 🏗️ SageMaker can now route requests by KV cache
On 16 November AWS made KV cache-aware routing available for SageMaker real-time endpoints in every region where SageMaker AI runs. You set the routing strategy `KV_AWARE` on a production variant and the endpoint steers requests toward instances already holding the prompt prefix, which AWS says cuts time to first token for long or repeated prompts. It needs vLLM Deep Learning Container 0.33.0 or later, GPU instances and at least two instances or inference-component copies. There's no additional charge.

It only pays off when prefixes repeat: long system prompts, shared documents, multi-turn chats.

**Try this:** on a staging endpoint with a repeated-prefix workload, compare default routing with `KV_AWARE`. Measure p95 time to first token.

[Source](https://aws.amazon.com/about-aws/whats-new/2026/11/sagemaker-kv-cache-routing/)
