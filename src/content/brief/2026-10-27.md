Three of today's stories share one uncomfortable shape: the dangerous setting was a quiet default or a number nobody compared. Start with the one that has a version to upgrade to.

## 🔥 A KV cache pool smaller than the context window leaked prompts between Cloudflare customers
Cloudflare's 26 October write-up covers its GLM-5.3 model on Workers AI. The prefill GPUs had a KV cache pool of 681,280 tokens against a 1,048,576-token context window, and an SGLang bug in disaggregated prefill/decode mode let over-length requests through, so decode read stale pages from earlier requests. Cloudflare says 155 responses were affected, all to prompts over 681,280 tokens, between 27 August and 9 September, with no evidence of deliberate exploitation.

If you serve long contexts in disaggregated mode, compare each node's KV pool with your context length today, and don't treat a 200 as proof the request was valid.

**Affected:** `@cf/zai-org/glm-5.3` on Workers AI (27 Aug to 9 Sep); operators running SGLang in disaggregated prefill/decode mode · **Fixed in:** SGLang v0.5.22 or later (the patch first shipped in v0.5.20) · **Severity:** no rating given; no evidence of deliberate exploitation · **Stopgap:** compare each node's KV pool size with the context length and lower the context length if the pool is smaller · **If compromised:** not stated in the advisory
[Source](https://blog.cloudflare.com/kv-cache-exposure-remediation/)

## 🚀 GPT-6.1 Terra is the cheap middle of OpenAI's lineup, and the numbers are OpenAI's
Terra is available from 26 October in the OpenAI API as `gpt-6.1-terra`, and AWS announced it generally available on Bedrock the same day. The model page lists $1 per million input tokens, $5 per million output, $0.05 for cached input, a 1,050,000-token context and 128,000 max output. AWS says it finishes agent tasks more than three times faster than GPT-6.1 Sol and GPT-6 Astra, at input and output prices at least 50% lower than Sol's. Simon Willison puts it in the slot Sonnet holds in Anthropic's lineup.

Cache writes cost $1.25 per million for 30 minutes and $2.50 for 12 hours, so a long agent loop is priced by how well it reuses its prefix. AWS ties the speed claim to OpenAI's Agents' Last Exam without describing its tasks, so treat it as a hypothesis for your own loop.

**Try this:** swap Terra into one existing agent eval, keep your current model as baseline, and compare cost per successful task.
[Source](https://developers.openai.com/api/docs/models/gpt-6.1-terra) · [AWS announcement](https://aws.amazon.com/about-aws/whats-new/2026/10/openai-gpt-6-1-terra-on-amazon-bedrock/) · [Simon Willison](https://simonwillison.net/2026/Oct/26/gpt-61-terra/) · [OpenAI changelog](https://developers.openai.com/api/docs/changelog)

## 🤖 A downloaded AGENTS.md can reconfigure Codex if you start it in the wrong folder
Forever Security published research on 22 October showing that a web page can silently drop an `AGENTS.md` (for Codex) or a `CLAUDE.md` (for Claude Code) into `~/Downloads`. If an agent is then started from that folder, Codex was steered into adding an MCP server to its machine-wide config and installing the npm package `function-color`, and the researchers say it ran the malware in more than 90% of attempts. Claude Code wrote `ANTHROPIC_BASE_URL` into its settings about half the time, which exposes its OAuth token. These are the researchers' figures.

For harness design: instruction files are executable input, and a working directory is a trust boundary.

**Affected:** Codex and Claude Code when started in a folder containing a planted AGENTS.md or CLAUDE.md (versions not stated) · **Fixed in:** no fix; the researchers say there is nothing for OpenAI or Anthropic to patch · **Severity:** not stated · **Stopgap:** don't start agents in Downloads, read unfamiliar instruction files first, keep approvals and sandboxing on · **If compromised:** rotate credentials and treat a machine with `function-color` installed as compromised
[Source](https://forever.security/blog/hijacking-ai-agents-via-downloads-folder)

## 🔬 Compaction loses your rules before it loses your code
A 22 October preprint tests five ways to compact an agent's context on PaperBench, ProgramBench and PostTrainBench, with the scaffold held fixed. No strategy beat plain self-summarisation, and discarding reasoning blocks or summarising with a small model cost some models up to 20 points on PaperBench. The sharper finding is what gets dropped: in real SWE-chat sessions, conduct instructions are dropped around 6 times more often than build specs, and on ProgramBench the first summary loses about one of the task's three anti-cheating rules.

The authors argue benchmarks flatter compaction because the goal is fixed and progress sits on disk. For a real session, that suggests re-injecting constraints after every compaction instead of trusting the summary to carry them.
[Source](https://arxiv.org/abs/2610.31778) · [Paper HTML](https://arxiv.org/html/2610.31778)

## ✍️ Simon Willison puts webframe through its paces
Willison had Claude Opus 5.5 evaluate webframe, Jeff Lindsay's Go tool that runs a page in a hidden system web view and sends `console.log` to stdout. His verdict is that it's a fast, lightweight JavaScript runner suited to scraping, with speed comparable to shot-scraper. The rough edges he lists are CSP failures, a 0x0 viewport, hanging loads and missing HTTP metadata.

It uses WKWebView, WebKitGTK or WebView2 rather than a bundled browser, so the same page can behave differently per OS. That's fine for scraping and a reason to keep your real sandbox where it is. Worth ten minutes if your agent tools shell out to a heavyweight headless browser today.
[Source](https://simonwillison.net/2026/Oct/26/webframe-evaluation/)

## 🏗️ Ubicloud's tool calls matched their schema 92% of the time until it turned on constrained decoding
Ubicloud wrote on 20 October about running Kimi K2.6 on vLLM 0.28, where the expected tool-call schema appeared only 92% of the time. The cause was a default: vLLM stopped enabling constrained decoding for requests that didn't ask for it. Enabling it server-side in vLLM 0.31 took the K2VV ToolCall benchmark from 92% to 100%, by Ubicloud's measurement.

If you upgraded your serving stack and agent reliability quietly slipped, a changed default is a better first suspect than the model. Pin the setting in your serving config and put a schema-conformance check in the deploy gate.
[Source](https://www.ubicloud.com/blog/fixing-tool-call-accuracy-in-vllm)
