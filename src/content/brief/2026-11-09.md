Defaults are doing a lot of work today: what an agent remembers, which model it routes to, how hard it thinks. The first one is the one to act on this morning.

## 🔥 Claude Code's "don't ask again" saved passwords in 1,122 public GitHub files
Choosing "Yes, and don't ask again" in Claude Code saves the full approved command as an allow rule in `.claude/settings.local.json`, password included. Apiiro's researchers, reported by The Hacker News on 7 November, found 104,185 copies of that file across 103,617 public repositories. 1,122 of them hold at least one secret.

```stats
1,122 | public copies of the file holding at least one secret
1,379 | distinct secrets in them (379 database passwords, 23 AWS keys)
215 | of those files that neither Gitleaks nor TruffleHog flagged
```

The file is meant to stay local, but Claude Code only adds it to your global git excludes, which doesn't travel with the project. Treat an agent's approval cache as a credential store: scanners miss it because the secret sits inside a command, after things like `PGPASSWORD=` or `sshpass -p`. The same bug was reported in August 2025 and closed by a bot as not planned in January. Apiiro did not test whether the secrets still work, though one notified company confirmed its key was live.

**Try this:** search your org for `.claude/settings.local.json` and `.claude/settings.json`, history included; count how many hold a literal password or token.

**Affected:** Claude Code projects that commit `.claude/settings.local.json` with approved commands in it; versions not stated · **Fixed in:** no fix is stated in the report or in issue #5544 · **Severity:** not stated · **Stopgap:** run `git rm --cached .claude/settings.local.json` and add it to the repo's own `.gitignore`, keep secrets in environment variables or a secrets manager, approve patterns such as `Bash(npm run:*)` instead of exact commands · **If compromised:** rotate every password, token and key the file has ever held before cleaning up

[Source](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html) · [GitHub issue #5544](https://github.com/anthropics/claude-code/issues/5544)

## 🚀 OpenRouter's Auto Code router picks the model for your coding agent
On 6 November OpenRouter launched `openrouter/auto-code`, a router for coding agents and harnesses, next to a rebuilt `openrouter/auto`. Auto Code starts in a higher cost tier, weighs speed heavily and penalises failures harder than the general router. There's no router fee: you pay the price of whichever model serves the request, and the response's `model` field says which.

OpenRouter's own numbers say Auto Code scores in line with Claude Opus 5.5 at 74% lower cost per task, across five benchmarks including Terminal Bench 4.0 and Deep SWE. A router moves model choice out of your code and into someone else's policy. That's a real saving, but log the served model on every call, or a regression becomes hard to reproduce.

**Try this:** run the coding eval you already trust twice, once pinned to your current model and once through `openrouter/auto-code`. Compare cost per solved task, and note which models actually served.

[Source](https://openrouter.ai/blog/announcements/auto-and-auto-code-routers/)

## 🤖 OpenAI's Agents SDK alpha changes two defaults you'll feel
The 0.24.0-alpha.7 pre-release, published on 8 November, switches the default reasoning effort from `low` to `medium` for `gpt-6-astra`, `gpt-6.1-sol` and `gpt-5.6-sol`. Set `reasoning_effort` to `low` in `model_settings` to keep the old behaviour. New Environments also default to `write_policy="strict"`, which needs a compatible Linux or macOS executor; `"legacy"` with `writable_roots=None` brings back the previous remote policy, including on Windows.

Silent defaults are how an upgrade becomes a cost and latency change: higher effort usually means more tokens and slower turns on the same prompts. Pin effort explicitly and rerun your evals before the stable release lands. It's an alpha, so the defaults may still move.

[Source](https://github.com/openai/openai-agents-python/releases)

## ✍️ Ten times the pull requests, no mandatory human review: one engineer's account
Neil Kakkar's essay, which won The Pragmatic Engineer's reader-essay contest and ran on 3 November, says he went from roughly 8–20 merged PRs a month to 200+ at the AI-native startup Tano, "approximately a tenfold increase". Tano largely dropped mandatory human code review, with an automated review agent handling most PRs, and fixes forward instead. He estimates the usage would cost $8,000+ a month at API rates; in practice the team is on Claude Max plans.

The new constraints he names are context switching, lost shared context and AI usage limits. If review stops being the gate, the safety net has to move somewhere: tests, fast rollback, observability. Per-developer token budget becomes a design input, not an afterthought. These are one engineer's self-reported figures, so read them as a data point, not a benchmark.

[Source](https://newsletter.pragmaticengineer.com/p/how-software-engineering-is-changing)

## 🏗️ Microsoft: attackers are using agentic tooling to find and use exposed secrets
Microsoft's threat intelligence team wrote on 5 November that GitHub secret-scanning queries began in August, followed by service-principal sign-ins with stolen application credentials from 28 October. In one case the actors took Key Vault and Storage data and abused Azure AI services.

A credential in a public repo gets found by automation, and it stays usable until someone revokes or rotates it. Prefer managed identities over static secrets, and treat AI API keys as targets. The Conditional Access block covers only single-tenant apps registered in your own tenant, so don't count on it as your only control.

**Affected:** Azure and Microsoft 365 tenants whose application credentials or AI API keys are exposed in public repositories · **Fixed in:** not applicable, no product patch · **Severity:** not stated · **Stopgap:** block 199.19.77.84 and the Tor exit node 199.19.77.18 with Conditional Access for workload identities (Workload ID Premium), turn on GitHub push protection, move to managed identities · **If compromised:** assume compromise, revoke sessions, PATs and SSH keys, remove client secrets, certificates and federated credentials, and rotate the contents of readable Key Vaults; tokens already issued stay valid until they expire

[Source](https://www.microsoft.com/en-us/security/blog/2026/11/05/threat-actors-use-agentic-ai-tooling-to-find-and-abuse-exposed-secrets/)
