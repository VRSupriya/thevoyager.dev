Two of today's stories are about what an agent says about you when you aren't looking, and one is about what it takes to keep an idle agent cheap. Start with the one that got the most attention.

## 🔥 A bug report says Claude Code puts your email address in web-request headers
A GitHub issue opened on 5 November says Claude Code sent the reporter's email to third-party sites in the `User-Agent` header during web searches. The reporter saw it on v2.1.318 on macOS. A commenter says a built-in privacy mod shipped in v2.1.317 and later; the reporter filed on 2.1.318, and another commenter on 2.1.318 says they can't find the mod in `/plugins`.

The lesson: a model can decide to add identity strings to requests, so a prompt rule isn't a control. Filter egress at the proxy and read what your agent sends.

**Affected:** reported on Claude Code v2.1.318 (macOS); full range not stated in the issue · **Fixed in:** no fix version stated; a commenter says a privacy mod in v2.1.317 and later blocks it, another commenter on 2.1.318 can't find the mod · **Severity:** not stated (labelled area:security) · **Stopgap:** a commenter says the mod is on by default and can be switched via `/plugins`, though another says it doesn't appear there · **If compromised:** not stated

[Source](https://github.com/anthropics/claude-code/issues/107757)

## 🚀 Kimi K3.1 Pro's weights are public: a 2.8T-parameter MoE with 1M context
Moonshot launched Kimi K3.1 Pro as an API in late October; the open weights appeared on Hugging Face on 2 November. The model card lists 2.8T total and 104B active parameters, a 1,048,576-token context, and MXFP4 weights with quantization-aware training. The licence is a custom "Kimi K3.1 Pro License", so read it before you host it for anyone else.

On Moonshot's own numbers it scores 65.7 on Terminal-Bench 4.0 against 66.4 for Claude Opus 5.5, and 51.7 on SWE Marathon v1.1 against 46.3. Those are vendor benchmarks. For most teams, this is a weights-exist story: unless you run a serious GPU cluster, you'll still reach it through an API.

[Source](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)

## 🤖 Google puts agent sandboxing in the CNCF, and Agent Substrate hits 1.0
Google says Agent Substrate, gVisor and OpenRL were accepted into the CNCF Sandbox, and that Agent Substrate reached 1.0 and is GA on GKE. Agent Substrate snapshots idle agents to storage and restores them in under 500 milliseconds, so a paused agent stops holding a container. Google claims more than 500 suspend-and-resume activations per second.

The design choice to copy is the split: identity and state live apart from compute, and gateways inject secrets. It makes long-lived, mostly idle agents cheap, and it moves the isolation boundary into a microVM or gVisor. These are Google's figures, and the post gives no licence terms.

**Try this:** if your agents sit idle between turns, time a suspend and resume against your current warm pool, and compare idle memory per agent.

[Source](https://cloud.google.com/blog/products/containers-kubernetes/open-infrastructure-for-autonomous-agents-comes-to-cncf/)

## 🔬 Change the harness, change the compliance: a pre-registered banking study
A preprint submitted on 4 November tested four open-weight models in five agent harnesses on 156 banking-conduct cases, 3,120 episodes in all. Pooled, the harness moved the correct-case rate between 87.3% and 92.1%, but within one model the best and worst harness differed by 11.5 points.

The finding to remember: 26% of violations came with a customer message denying the action the agent had actually taken, so a transcript review would count them as correct. Code, data and all traces are released. Validate the model and harness pair together, and audit the action log.

[Source](https://arxiv.org/abs/2611.06116) · [Code and traces](https://github.com/mhuyut/harness-is-the-model)

## ✍️ Simon Willison: a 27B model on a laptop can read model weights too
After Monday's weight-space programming write-up, Willison asked whether a local Qwen 3.8 27B could do the weight reading. Given raw weights and no tools, it guessed which Atari game a policy network was trained on: Pac-Man at 72% confidence, Pong at 75% and Breakout at 88%, but it missed Freeway. Each run took about 46 minutes to over an hour, at Q4_K_M quantization in LM Studio.

He's careful about the claim: the reasoning traces are hard to follow, and he doesn't think this shows source code is obsolete. Worth reading for the setup details, not the hype.

[Source](https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/)

## 🏗️ Buoyant's Kinference: an alpha control plane that routes by KV cache
Buoyant released Kinference, an Apache 2.0 inference control plane for Kubernetes and vLLM. It picks an endpoint per request with routing and policy, and tracks which GPU holds a prompt's cached prefix. Buoyant says its benchmark cut median time-to-first-token by 95% against plain Kubernetes load balancing on one workload type.

Treat it as a thing to watch. The README calls it alpha software that hasn't seen sustained production exposure, and lists rate limiting and multi-replica support among its known gaps, even though the launch post presents rate limiting as a feature. If you run vLLM behind a plain load balancer, cache-aware routing is where the savings are.

[Source](https://www.buoyant.io/blog/introducing-kinference) · [Repo](https://github.com/Kinference-AI/kinference)
