Most of today is about agents doing real work, on both sides of the fence: attackers running them against exposed servers, and builders giving them a voice and a task board.

## 🔥 Microsoft explains ARTEX, the agent toolkit attackers have started using
Microsoft's security team published a write-up on 25 November of ARTEX, an agentic AI framework that threat actors are abusing. It says it has seen Crystal Typhoon and Salt Typhoon integrating ARTEX into their tooling. You may see it linked to a breach at US intelligence agencies; Microsoft's post doesn't say that, so treat that link as unconfirmed.

There's no product to patch here, which is the awkward part. Microsoft says the most reliable signal is behavioural: machine-speed request bursts, web server processes spawning shells or curl, and fast reads of `.env` files, private keys and cloud credentials. If your web tier can read secrets, an agent will find them faster than a human would.

**Affected:** no product vulnerability; targets internet-facing web apps and secrets in code or config · **Fixed in:** not applicable, no patch · **Severity:** not stated in the advisory · **Stopgap:** WAF in prevention mode with rate limiting, restrict outbound connections from web servers, phishing-resistant MFA · **If compromised:** invalidate and replace any secret found in code or configuration files, and turn on automatic attack disruption

[Source](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/)

## 🚀 Amazon Transcribe Turbo is a speech model built around voice-agent turn-taking
Amazon put Transcribe Turbo in public preview on 25 November, in US East (Ohio), covering streaming and non-English batch; English batch Turbo is already GA in most Regions. It says the word error rate in English drops about 14% relative to the current production model for streaming, and that semantic turn-taking responds in about 615 ms with a 5% interruption rate. With runtime hints, menu routing in customer-service data went from 87% to 97%, all AWS's own numbers.

For anyone building voice agents, the turn-taking number matters more than the WER: it's what decides whether the agent talks over people. Streaming is preview and Ohio-only, so this is a test, not a migration.

**Try this:** replay a sample of your recorded calls through Turbo and your current model. Baseline: your current interruption rate. Metric: interruptions per 100 turns.

[Source](https://aws.amazon.com/about-aws/whats-new/2026/11/transcribe-turbo-preview/)

## 🤖 Vercel Board gives people and coding agents one place to claim tasks
Vercel's Board is a headless message board used from a CLI or JS SDK, where tasks are threads. A worker claims a task with a lease of up to five minutes that it has to keep renewing, and a second claimer gets `task_claimed`. Channels sync with Slack, GitHub and Linear. Vercel calls it experimental and says its v0 software factory, rebuilt on Board, merges over 50% of PRs, which is Vercel's own claim.

The lease is the nice idea: a crashed agent frees its task on its own, with no lock to clean up. The catch is in the docs: Board grants don't apply on Slack, GitHub or Linear, so a private Slack channel synced into an open board channel can be read by the whole team.

[Source](https://vercel.com/blog/introducing-vercel-board) · [Board docs](https://vercel.com/docs/board) · [Task docs](https://vercel.com/docs/board/concepts/tasks) · [InfoQ](https://www.infoq.com/news/2026/11/vercel-board-agents/)

## 🔬 SpecEngineeringBench: coding agents pass the tests but miss the spec
A new benchmark of 100 instances from 78 open-source Python repos asks agents to write the specification, not just the code. Across seven frontier coding agents it reports a 91.47% Head Pass Rate but only a 26.36% Fail-to-Pass Rate, and localisation recall falls from 78.11% at file level to 51.29% at function level.

If you gate agent output on "tests pass", this says the gate is weaker than it looks. It's a benchmark paper with its own metrics, so run it against your own repos before you change a process.

[Source](https://huggingface.co/papers/2611.32973)

## ✍️ Philipp Schmid cut most of his rules when he moved to Gemini 4 Neon
In a post on 25 November, Philipp Schmid lists five changes to how he sets up context for Gemini 4 Neon: fewer strict rules (his user-level GEMINI.md fits on one screen), tool rules stated once in typed JSON schemas with enums and no few-shot examples, most project AGENTS.md files deleted in favour of skills loaded on demand, screenshots as references, and handing off context between phases instead of compacting.

It's one person's anecdotal experience; he says fewer rules cut wasted thinking and raised accuracy, but gives no measurements. Still, "delete half your instructions and see what breaks" is a cheap experiment, and the shorter file is easier to review.

[Source](https://www.philschmid.de/gemini-4-neon-context-engineering)

## 🏗️ A bank-report agent design where release gates carry the weight
InfoQ's architecture article on 24 November proposes a multi-agent system for drafting suspicious activity reports. Grounding is the base: the system should refuse to draft when evidence is missing. Releases pass six stages (version, test, gate, shadow and canary, monitor, rollback), and the gates need sign-off from engineering, compliance, risk and legal depending on the change type.

It's a proposed design from an architect-certification programme, not a deployment, and it reports no measured results. What's worth borrowing is the refusal rule and the idea that a prompt change is a release with an approver, not a quiet edit.

[Source](https://www.infoq.com/articles/llm-agent-architecture-evals-grounding/)
