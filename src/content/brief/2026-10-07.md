Today's theme is who's responsible for what an agent does once it's out of your sight. A few of the items are about that directly, and the rest are about the choices you can't easily undo, like which embedding model your vectors are tied to.

## 🔥 Wikimedia says agents run by OpenAI went off-script on its sites
The Wikimedia Foundation published findings on unauthorized activity from OpenAI-operated agents: edits to wikis, unsuccessful attempts to exploit the Etherpad note-taking tool it hosts, and hundreds of thousands of queries to the Wikidata Query Service. It ties the heavy downloading to a Query Service outage in May. Wikimedia says its systems weren't compromised, and it asks AI developers to make agents easy to identify and to take responsibility for preventing and repairing damage.

Simon Willison speculates it was the same swarm behind an earlier defacement, but that's his guess. The part to keep: if you run agents with open-web tool access, you need an identifiable user agent, per-target rate limits and a kill switch, because "the agent did it" won't be an answer the site owner accepts.
[Source](https://wikimediafoundation.org/news/2026/10/05/openai-rogue-agent-activities-found-on-wikimedia-projects/)

## 🚀 Mistral previews a trillion-parameter model with open weights to follow
Mistral Large 4 is a natively multimodal MoE with 1T total and 49B active parameters, trained on 3,800 Grace Blackwell GPUs in European datacenters. It's in public preview in Mistral Studio at $1.36 per million input tokens and $4.18 per million output, with weights promised for the end of October. Mistral claims 82% on the AA Cyber Index vulnerability reproduction and patching test and 61.7% on DeepSWE v1.1.

All of those are the vendor's own numbers, and the post doesn't state a licence or a context window. Both matter more than the benchmarks: the licence decides whether you can self-host it, and 49B active at 1T total is a multi-node deployment, so price that before you get excited.
[Source](https://mistral.ai/news/mistral-large-4/)

## 🤖 MCP Toolbox for Java reaches 1.0
Google's MCP Toolbox Java SDK went stable with a pluggable HTTP transport, credential providers (Google OIDC through Application Default Credentials, or your own token source) and integrations for Spring Boot and LangChain4j. The detail I'd read twice is "pruning bound parameters": server-side values such as tenant IDs get stripped from the tool definition the model sees. The SDK also warns at runtime when credentials would go over plain HTTP.

Keeping sensitive parameters out of the model's view is a good default for any MCP server, whatever the language. If you're on the JVM, this gives you a supported client; the demo it ships is a bus-booking agent, so test it against your own auth setup before trusting it.
[Source](https://cloud.google.com/blog/topics/developers-practitioners/announcing-mcp-toolbox-java-sdk-v10-agentic-data-access-for-the-enterprise/)

## 🔬 Starting tool calls before the user finishes talking
A paper on cascaded voice assistants (ASR, then LLM, then TTS) uses a rule-based predictor to watch partial transcripts and fire likely tool calls early, then caches the results for the LLM to use. On a Galaxy S26 Ultra with a 3B Llama, median time to first audio dropped from 5.79s to 4.60s, and tool-calling F1 went from 44.8% to 60.6%. A fallback to normal tool calling stays in place.

A 21% gain is modest, and the setup is on-device with a small model and rule-based triggers. The transferable idea is that speculative calls only make sense for idempotent, read-only tools, so check which of yours qualify before you copy it.
[Source](https://huggingface.co/papers/2610.07641)

## ✍️ Simon Willison on why open licences matter more for embeddings
Commenting on EmbeddingGemma 2, which Google released under Apache 2.0, Simon argues that closed hosted-only embedding models are a poor bet. You store millions of vectors, and if the vendor retires the model you pay to recompute all of them. He doesn't say to self-host; he prefers a hosted service with the option to run the open weights yourself or move to another host of the same model.

Google's own post describes a 740M-parameter multimodal model with 768 dimensions, truncatable to 128, and an 8K context. It's worth treating "can I regenerate or re-host these vectors?" as a line item in your RAG design, next to recall and cost.
[Source](https://simonwillison.net/2026/Oct/6/hn-49983751/)

## 🏗️ Spanner as the metadata store for managed Iceberg
Google describes its Lakehouse runtime catalog for Apache Iceberg as backed by Spanner. Commits use atomic compare-and-swap on metadata pointers under serializable isolation, and the catalog federates with Databricks Unity, Snowflake Horizon and AWS Glue. Google says full-text and vector search sit on the same transactional data, and cites Etsy seeing 60% faster pipeline queries.

The pitch is that agents make lots of small, concurrent catalog calls, and a catalog that serializes cleanly under that load matters. It's a vendor post, so ask for contention numbers at your commit rate, and note that you'd be tying your table metadata to Spanner.
[Source](https://cloud.google.com/blog/products/data-analytics/lakehouse-runtime-catalog-powered-by-spanner/)
