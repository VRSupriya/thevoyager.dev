A loud day for advisories and a quiet one for flagship launches. The useful work today is a version audit and one look at your cache sizing.

## 🔥 A normal LiteLLM proxy user can become admin, then run code
An advisory for the LiteLLM proxy was added to the GitHub Advisory Database on 27 October. Cross-domain reuse of the salt key lets an authenticated `internal_user` escalate to `proxy_admin` and reach remote code execution, scored 9.9 (Critical) on CVSS v3. It is a separate issue from the 1.107.0 supply-chain compromise we covered last week.

If your proxy fronts several teams, the gap between "can call models" and "can administer the gateway" was one flaw wide. The stopgap costs something real: turning off the experimental UI login also breaks CLI SSO and Claude Code gateway login, so patch rather than live with it.

**Affected:** 1.91.0–1.100.3, 1.101.0–1.101.2, 1.102.0–1.102.1, 1.103.0, 1.104.0rc1 (1.87.0–1.90.x only if `EXPERIMENTAL_UI_LOGIN=true`) · **Fixed in:** 1.100.4, 1.101.3, 1.102.2, 1.103.1, 1.104.0rc2 · **Severity:** 9.9 Critical (CVSS v3) · **Stopgap:** set `EXPERIMENTAL_UI_LOGIN=false` · **If compromised:** not stated in the advisory beyond upgrading to a patched version as soon as possible.

[Source](https://osv.dev/vulnerability/GHSA-7hp6-4w63-5g45) · [GitHub advisory](https://github.com/BerriAI/litellm/security/advisories/GHSA-7hp6-4w63-5g45) · [The Register on the 1.107.0 compromise](https://www.theregister.com/security/2026/10/21/litellm-supply-chain-attack-hoovers-up-passwords-and-secrets/5304548)

## 🚀 Liquid AI's LFM3 puts text, vision and voice into roughly 2B-class models
Liquid AI's LFM3 cards on Hugging Face list LFM3-1.7B (text, 256K context), LFM3-VL-2B (vision, 128K) and LFM3-Omni-2B (text, image, video and audio in; text or speech out, 32K). All three use the LFM Open License v1.0. The 1.7B card targets local agents, tool calling and structured output, and says it is not recommended for agentic coding.

Treat the numbers as Liquid's own: IFEval 96.66 and BFCL V4 71.39 for the text model, and the cards show Qwen3.5-9B ahead on several tests. For on-device routing or extraction, this is a cheap model to put against whatever small model you run today.

**Try this:** run LFM3-1.7B on 50 of your real tool-call traces against your current small model. Metric: valid-call rate at equal latency on the same hardware.

[Source](https://huggingface.co/LiquidAI/LFM3-1.7B) · [LFM3-Omni-2B](https://huggingface.co/LiquidAI/LFM3-Omni-2B) · [LFM3-VL-2B](https://huggingface.co/LiquidAI/LFM3-VL-2B)

## 🤖 MCP's C# SDK 2.0 drops the session handshake
The official C# SDK for MCP, maintained with Microsoft, reached 2.0, implementing the 2026-07-28 spec revision. HTTP is stateless by default: the `initialize` handshake and the `Mcp-Session-Id` header are gone. Tools can now ask for more input mid-call by throwing `InputRequiredException`, and the client re-issues the call with the answers.

That removes the sticky-session requirement behind a load balancer, which is the real win for anyone running MCP servers at scale. The cost is breaking changes: Tasks moved to an opt-in package, and OAuth is stricter, with RFC 9207 issuer validation and mandatory advertised PKCE S256 support. Check which of your servers quietly relied on sessions.

[Source](https://www.infoq.com/news/2026/10/MCP-CSharp-SDK-Stateless/)

## ✍️ LangChain's design agent: one sandbox per Slack thread, rules deleted as models improved
LangChain's team describes Content Studio, an internal agent on Managed Deep Agents that makes decks and motion graphics in code. Each Slack thread gets its own Linux sandbox, and stage order is enforced in code rather than in prompts. They report the median request cost falling from about $8 to about 50 cents.

The lesson that travels is about deleting. Most hard-coded rules were removed after Opus 5.5, and the memory file is capped at a 200-line index after an early version reached 500K tokens. The figures are self-reported and the post promotes LangChain's own products.

[Source](https://www.langchain.com/blog/design-agent)

## 🏗️ KV cache hit rate decides when chat latency falls off a cliff
At QCon AI, Momento's Khawaja Shams showed a small vLLM experiment: a 4B FP8 model, a 10,000-token system prompt and 12-turn agentic-coding-style sessions. With 12 concurrent sessions p99 time to first token was 2.6 s; at 14 it was 38.9 s. Adding 16 GB of DRAM as a cache tier brought p99 back to 3.5 s, and 32 GB moved the cliff from 14 to 28 sessions.

Two GPUs without session affinity reached 128 tok/s, and with affinity 201 tok/s. So routing is part of capacity planning, not an afterthought. It is one speaker's small test, not a production benchmark.

[Source](https://www.infoq.com/presentations/llm-inference-kv-cache/)
