Two things this morning have a price tag: a routing layer that claims to halve coding cost, and a vLLM patch you can book in today. Everything else can be read with coffee.

## 🔥 Copilot Fusion picks the model for each coding task
GitHub made Copilot Fusion generally available on 28 October. You choose an effort level (Standard, High or Max) and a workflow (Single, Cascade or Critique), and Fusion decides which models handle the work. It runs in VS Code, the Copilot app, Copilot CLI and JetBrains, on all Copilot plans.

GitHub says Fusion Max scored 60 on the Artificial Analysis Coding Agent Index, within two points of Claude Code with Opus 5.5 Max, at about half the average API cost per task and about 40% less time. Those are GitHub's numbers, and the page doesn't say who ran the cost and time measurements.

```stats
60 | Fusion Max on the Artificial Analysis Coding Agent Index (Opus 5.5 Max: within two points)
~50% | of the average API cost per task (GitHub's figure)
30% | limited-time discount on model costs for paid plans
```

The design point is that model choice moves from your config into a router, billed at each model's standard rate. Admins keep control: Fusion only uses models your org policy enables. An experimental preview also routes between local and cloud models, with the routing decision made in the cloud.

**Try this:** run Fusion Standard against your current default on 20 recent tickets. Metric: cost per merged change, with your merge rate as the baseline to hold.

[Source](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion) · [Local-model routing](https://github.blog/changelog/2026-10-28-github-copilot-fusion-now-supports-selection-of-local-models)

## 🚀 Gemini 4 Carbon starts with cyber defenders, not developers
Google announced Gemini 4 Carbon on 28 October as a limited release: it goes first to a subset of cyber defenders, then more trusted partners through the Fairwind Program, with broader access "coming soon". Introductory pricing is $2 per million input tokens and $10 per million output, rising to $4 and $20 after the introductory period.

The scores are Google's own: 59 on the Artificial Analysis Intelligence Index v5.0 (ranked first), 88.2% on SEC-bench Pro, 54.8% on ExploitGym and 0.0% prompt-injection attack success on Gray Swan, against 0.7% for Gemini 4 Argon. It's a limited release, so there is little to wire into a router yet.

Watch it rather than plan around it. If you build security tooling, the interesting part is a frontier lab choosing a gated rollout for a model it markets on exploit skill.

[Source](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/)

## 🤖 Foundry's Copilot harness is in preview, and the meter starts on 1 December
Microsoft put the Copilot harness in Foundry Agent Service into public preview on 28 October, and made long-running resilience for hosted agents generally available. You pick the harness when you create an agent; existing agents are unchanged.

Runtime is free before 1 December. After that, sandbox compute is billed at $0.0994 per vCPU-hour and $0.0118 per GiB-hour. An agent that sits idle in a sandbox for a day has a real cost, so size and timeouts become design decisions rather than defaults.

**Try this:** price one of your hosted agents at those rates for a week of expected sandbox hours, then decide before the free period ends whether it stays hosted.

[Source](https://devblogs.microsoft.com/foundry/microsoft-copilot-harness-in-foundry/)

## 🔬 Group memory fails on attribution, and a perfect relevance filter doesn't fix it
A preprint asks what a compressed memory of a multi-agent discussion should keep. On CrossProfile, a 60-template, 480-task diagnostic, relevance selection keeps on-topic decoys, and keeping the rarest claims is no better than random on average. Even a perfect relevance filter loses 23 to 31 points to rarest-first in the classic hidden-profile setup.

The practical finding is about attribution: removing or randomizing the tags that say which agent said what raised accuracy by 13 to 24 points, because the decision model leans toward facts many agents mention. The models are small (Qwen2.5-7B, Llama-3.1-8B and two DeepSeek models), so check it on yours first.

[Source](https://huggingface.co/papers/2610.37624)

## 🏗️ vLLM 0.32.0 closes two remote-code-execution paths
Eight vLLM advisories were added to the GitHub Advisory Database on 28 October, all fixed in 0.32.0. Two matter most. GHSA-h3rc-j82p (CVSS 8.1) lets image bytes labelled as a PNG reach the host's Ghostscript, which gives command execution on hosts with a vulnerable Ghostscript. GHSA-6757-hggm (7.5) concerns `--mm-processor-cache-type shm`: an authenticated caller can forge a shared-memory handle so the worker unpickles attacker-staged bytes, even with `VLLM_ALLOW_INSECURE_SERIALIZATION=0`.

The rest are crashes and exposure: a CORS default of `*` with no auth unless an API key is set, chat-template abuse, and engine-crashing inputs for Phi-4 audio, DeepSeek-OCR and out-of-vocabulary tokens. Keep the API key on and treat the multimodal path as an attack surface. Upgrading to 0.32.0 also includes yesterday's code_revision fix (0.31.0, only with `--trust-remote-code`).

**Affected:** vllm (pip) below 0.32.0 · **Fixed in:** 0.32.0 · **Severity:** High 8.1 and High 7.5 for the two RCEs; the other six range from Low to Moderate · **Stopgap:** none listed for the two RCEs; hosts without Ghostscript, or with it patched for CVE-2024-29510, aren't exposed to the execution chain · **If compromised:** not stated in the advisories

[Source](https://github.com/advisories/GHSA-h3rc-j82p-2c3h) · [Shared-memory advisory](https://github.com/advisories/GHSA-6757-hggm-hp2w) · [CORS advisory](https://github.com/advisories/GHSA-vvpg-rrww-wpmh)
