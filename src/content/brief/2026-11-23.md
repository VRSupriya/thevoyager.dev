The thread today is how much you can run yourself: a 105B model on one card, extraction models you can download or rent, and a reminder to test plain grep before building a vector index.

## 🔥 Sarvam's open 105B model fits on one GPU
Sarvam published a new open-weight checkpoint of its 105B mixture-of-experts model on 22 November, aimed at customer-support and voice agents. The cards say Apache-2.0, 10.3B active parameters and a 131,072-token context.

```stats
65 GB | size of the NVFP4 checkpoint, which Sarvam says fits one 96 GB RTX PRO 6000 Blackwell
99 tok/s | decode speed for one user on a 10K-token prompt (Sarvam's own test)
$0.15 | blended price per million tokens, cut from $0.44 (Sarvam's figures)
```

Open models at this size usually mean a multi-GPU node, so this is worth a second look. Sarvam's eight-benchmark conversational-agent average goes from 42.6 to 73.9 on the new checkpoint, in Sarvam's own harness. The catch is that the kernel fix for that card is an open vLLM pull request, so you're pinned to the tested vLLM 0.33.0 setup for now.

**Try this:** serve the NVFP4 build on one Blackwell-class card beside your current support-agent model, replay 50 real transcripts, and compare task success and p95 latency at four users.

[Source](https://www.sarvam.ai/blogs/sarvam-105b-1711) · [Model card](https://huggingface.co/sarvamai/sarvam-105b-1711)

## 🚀 Cloudflare opens its extraction models
Cloudflare announced on 18 November that Clairic (27B) and Clairic-flash (9B), its document-extraction models, are open-weight. The Hugging Face card says Apache-2.0 on a Qwen3.8-27B base, and both also run on Workers AI at $0.10 per million input tokens until 1 December (Clairic is $0.24 after that).

On Cloudflare's own test of 96 fresh-text requests, Clairic got 335 of 336 fields right and the flash model 328, at p50 latency of 358 ms against 155 ms. The post itself says there are no public extraction benchmarks yet, so treat those as a starting point.

Extraction is a good fit for a small model: the schema is fixed, so it's easy to score field by field. And since the API schemas didn't change from the preview, you can start hosted and move to your own GPUs later.

**Try this:** run your 100 hardest documents through both models and compare field-level accuracy and p50 latency before choosing.

[Source](https://blog.cloudflare.com/open-clairic) · [Model card](https://huggingface.co/cloudflare/clairic)

## 🔬 Embeddings vs grep for code search
A preprint submitted on 16 November argues that dense retrieval's lead in code search comes from how it's been evaluated. The authors build Repo-Premium (six languages, over 91 repositories) and find that queries lacking rare identifiers favour dense retrieval. Having an LLM write likely identifiers first ("generate-then-grep") helps BM25 more than dense, letting it match dense in every Python pool.

They found no method that predicts which retriever wins per query, and recommend a fair lexical baseline, fusing dense with BM25, and adding identifiers to queries.

Before you stand up a vector index for a coding agent, start with that cheap baseline. If it ties, you've saved an index to keep in sync.

[Source](https://arxiv.org/abs/2611.20455)

## 🏗️ AWS Lambda now serves vLLM on GPUs
AWS announced on 18 November that Lambda Managed Instances now run on EC2 G-series GPU instances. Per the docs, each execution environment gets one GPU, concurrency defaults to 4 and tops out at 48, and Lambda runs multiple invocations concurrently in each execution environment. AWS ships vLLM and SGLang base images.

You pay the EC2 On-Demand price plus a 9.75% management fee and $0.20 per million requests, and the default EC2 quota for G instances is 0 vCPUs, so request an increase first. That makes it a fit for bursty traffic with scale-to-zero, less so for steady load where the fee adds up.

The limit that matters is memory: GPUs top out at 48 GB (L40S), so a 65 GB checkpoint like today's Sarvam build won't fit.

[Source](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-gpu-managed-instances/) · [Docs](https://docs.aws.amazon.com/lambda/latest/dg/lambda-managed-instances-gpu.html) · [Pricing](https://aws.amazon.com/lambda/pricing/)
