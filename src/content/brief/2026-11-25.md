Most of today is about limits you set yourself: which domains an agent may call, how much it may spend, how much memory a model needs before you commit to it.

## 🔥 Foundry turns agent egress and spend into settings you can audit
Microsoft's Ignite roundup for Foundry, published on 24 November, makes hosted-agent network egress controls generally available. They decide which destinations an agent can reach from outside its sandbox, and the post suggests starting in Audit mode before you switch to Enforce. Cost controls are in public preview: budgets that alert and block, but not for tool charges, hosted-agent compute or provisioned throughput.

Two details matter. Agent controls, also in public preview, score proposed actions with rules, classifiers and LLM judges, but the service only returns a decision and your agent host has to enforce it. And a budget block comes back as HTTP 429, which the post says not to retry as ordinary throttling, so your retry logic needs to tell the two apart.

**Try this:** run one hosted agent in Audit mode for a week and compare the destinations it actually reaches with the list you'd have written from memory. Metric: the number of domains you didn't expect.

[Source](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-ignite-2026/)

## 🚀 Kolibri 1.1 is a 75B open MoE that only wakes 3.4B at a time
Aleph Alpha released Kolibri 1.1 on 23 November: open weights under Apache 2.0 (weights and config files only), 75B parameters in total and 3.44B active, German and English; the card describes a text model. The context window is 262,144 tokens natively and up to 1,048,576. On its own card it claims 70.4 on SWE-Bench Verified and 93.0 on Tau2-Bench Telecom, which are the vendor's numbers. The same table has Qwen3.8 Flash Next ahead overall, 80.1 against 73.2.

The catch is memory, not compute: it needs about 77.6 GB, and the card's minimum is two H100 SXM5s (it recommends four), even though each token touches few parameters. I'd call it a serious candidate if German-language data has to stay in Europe, and not a reason to switch if it doesn't.

[Source](https://huggingface.co/Aleph-Alpha/Kolibri-1.1)

## 🤖 iFood runs coding agents as an async job service, not a chat window
iFood built a Remote Agents Platform: a REST API that runs agentic coding tasks in isolated remote sandboxes and returns the result later, such as a merge request. According to OpenAI's customer story, it covers 15,000 repositories, has completed more than 25,000 runs and used more than 27 billion tokens, at an average inference cost of US$0.04 per run. It runs on GPT-5.6 Luna.

The pattern is the interesting part. Submit a task, get a merge request back, review it like any other: that's easier to audit and budget than an agent sitting in someone's editor. These are vendor case-study numbers, with no dollar savings given.

**Try this:** pick one chore that repeats across many repos, such as a dependency bump, and run it through a sandboxed agent job. Baseline: the hours it takes by hand. Metric: the share of merge requests your reviewers accept without edits.

[Source](https://openai.com/business/customer-stories/ifood)

## 🔬 SupportChain says a 9B reader can beat a 20B one on multi-hop QA
A preprint submitted on 21 November, with a single author, aggregates several quote-grounded reasoning chains from a small reader, weighting them by how well the quotes support each answer. Using a 9B reader under the HippoRAG 2 protocol, with no index built, it reports 63.0 F1 on MuSiQue, where the previous best was 59.2 with a 20B reader. The reliability model needs only 100 answered training questions.

For an architect this swaps model size for extra calls per question, so latency and cost move rather than vanish. These are the author's own results on research benchmarks; check them on your own multi-hop questions first.

[Source](https://arxiv.org/abs/2611.28519)

## ✍️ Simon Willison counts three step changes in twelve months
In a post on 24 November, Simon Willison names three inflection points. The first, in November 2025, was when coding agents became reliable: Opus 4.5 was the first model where the default result in Claude Code was generally right. The second, around June and July 2026, was "Fable-class" models: give one a goal and the right tools and, in his words, "watch it cook". The third, in September and October, was 3D modelling and game design, where Opus 5.5 playtested and rebalanced his strategy game over 12 hours. He isn't sure whether Fable 5.2 is a fourth.

It's first-person and anecdotal, so read it as a field report. The design point I'd take: if a model can keep working for hours with the right tools, your tool surface and your checks matter more than the prompt.

[Source](https://simonwillison.net/2026/Nov/24/llm-inflection-points/)

## 🏗️ A JPMorganChase talk puts a price on idle GPUs
At QCon AI Boston, Dio Rettori of JPMorganChase estimated a 3-year total cost of $16M to $20M for 64 NVIDIA B200 GPUs. He says that's his rough estimate, not what the bank paid, and that his views are partly personal. He cites a Cast AI report of 5% GPU utilization, and in a multi-agent demo on a laptop RTX 5080 he showed response-time variation of 41% for cloud calls against 5.2% on-prem, a metric he doesn't define precisely.

Take the utilization figure as the useful part: at that rate, buying hardware is mostly a scheduling problem. And in agent chains the tail matters more than the average, because each hop adds its own variance.

[Source](https://www.infoq.com/presentations/enterprise-ai-inference-architecture-costs/)
