A bill under $200 in tokens turned up a critical bug in the JDK, and the model OpenAI shipped the same day is having a bumpy first week. Start with the bug.

## 🔥 Codex found a critical OpenJDK bug (Java4Shell) for under $200
Calif says the Base64 decoder intrinsic in OpenJDK's x86-64 code can be fed padded, malformed input that makes it write 62 bytes past its output array on CPUs with AVX-512 VBMI. That can leak heap memory or, with enough grooming, run code. It's CVE-2026-114938, rated 9.2 (CVSS 4.0) by Calif, disclosed on 17 November.

The AI part: researcher Quang Luong pointed OpenAI Codex at HotSpot, and Calif says the total token cost was less than $200, about an hour to find the bug and two more to build the exploit.

If Java runs next to your AI stack (Kafka, Elasticsearch, a gateway), check CPU flags before JDK versions. Calif says each target needs its own exploit work, which buys time but not much.

**Affected:** OpenJDK 17.0.6 or newer and the distributions built on it, on x86-64 CPUs with AVX-512 VBMI; ARM64 is not affected · **Fixed in:** Calif's write-up gives no fixed build numbers; Endor Labs reportedly lists Oracle Java SE 17.0.21.1 and 21.0.13.1 as fixed, and says to confirm a build includes the JDK-8393212 fix · **Severity:** CVSS 4.0 9.2, CRITICAL, per Calif · **Stopgap:** `-XX:-UseBASE64Intrinsics`, or `-XX:UseAVX=2` on x86-64 only · **If compromised:** not stated in Calif's write-up

[Source](https://calif.io/java4shell/) · [Endor Labs](https://www.endorlabs.com/learn/java4shell-unauthenticated-rce-reported-in-openjdk-17-cve-2026-114938)

## 🚀 GPT-6.2 Astra and Sol: cheaper per token, with a price step past 272K
OpenAI released GPT-6.2 Astra, its frontier model, and GPT-6.2 Sol, a cheaper everyday model, on 17 November. Astra is $8 per million input tokens and $40 per million output, with a 1,050,000-token window. Sol is $2 and $10 on OpenRouter. GitHub Copilot has both rolling out on Pro+, Max, Business and Enterprise plans.

The detail that changes a budget: on OpenAI's Astra page, input above 272K tokens doubles the input rate and raises output to 1.5x for the whole request, so a million-token window isn't a million-token price. First reviews are rough, with one investor calling the pair "essentially unusable" and another reviewer calling it uneven and hard to steer.

**Try this:** run 20 of your own agent tasks on Sol and on Astra with your current model as the baseline. Compare cost per accepted result.

## 🤖 Your coding-agent harness can change the bill by up to 5x
Runta's FrontierHarness v1.1, published on 17 November, ran 22 harness configurations across five open models on 62 terminal tasks, 27,280 runs in all, served by Baseten. With the model fixed, it says the harness changes cost by 1.8 to 5.0 times. The 5.0 is one pairing: with DeepSeek V4.1 Flash, Cline CLI cost 5.0 times as much as OpenCode v1 for 2.0 more points of pass rate.

Model choice still dominates: it explains 92.8% of cost-per-task variance against 2.3% for the harness. So pick the model first, then check whether your harness is quietly the expensive part. The caveat: costs are list-price estimates, and pass-rate intervals are about ±10 points, so small gaps are ties.

**Try this:** run the same 20 tasks through your current harness and one alternative on the same model. Compare cost per passing task.

[Source](https://runta.com/blog/introducing-frontierharness-eval-v1-1/)

## 🔬 K2-Horizon: a 375B model with the weights, data and recipe public
MBZUAI's Institute of Foundation Models published K2-Horizon on 16 November: six models from 0.9B dense to a 375B-A23B mixture of experts. The 375B has a 512K context window, and the model card tags it Apache 2.0 and says training data, recipe, code and intermediate checkpoints are public, and the paper's model table lists FP8 and NVFP4 builds.

The benchmarks are the team's own. The paper says the 375B ranks first or second on most agentic and coding benchmarks against four open peers, leading them on Toolathlon-Verified at 65.3, while the model card shows it behind closed models on most of its table (Terminal-Bench 2.1: 70.2 against a best of 80.9).

That makes it more interesting for sovereign or air-gapped work than for leaderboards. Check whether your serving stack handles a 23B-active MoE before getting excited.

[Source](https://arxiv.org/abs/2611.21003) · [Model card](https://huggingface.co/IFM/K2-Horizon-375B-A23B) · [Paper (HTML)](https://arxiv.org/html/2611.21003v1)

## ✍️ Simon Willison: keep the agent outside, run its code inside a sandbox
On 17 November Willison linked a Prime Radiant post on external sandboxes: the agent stays outside, and the code it runs executes in a dedicated sandbox. Prime Radiant released three demonstration servers (WebAssembly, Apple Containers and QEMU), all with the same localhost API. Two features matter most: an optional allow-list proxy for which hosts the code can reach, and a credential-replacement mechanism so authenticated calls work without the agent seeing the secret.

Read it next to today's PyPI story below. The pattern keeps untrusted code away from your keys, and the keys are what both attacks go after.

[Source](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/) · [Prime Radiant's post](https://blog.primeradiant.com/external-sandboxes-for-coding-agents/)

## 🏗️ Two malicious releases of Microsoft's agent-framework stole cloud tokens
On 17 November, `agent-framework` 1.26.1 (20:35 UTC) and 1.26.2 (21:08 UTC) appeared on PyPI; Aikido says both were removed by about 21:20. A `.pth` startup file runs a credential stealer on every Python start, even if the package is never imported. It collects environment secrets and Azure DevOps and managed-identity tokens, 1.26.2 adds GitHub Actions OIDC tokens, and the data goes to webhook.site. Aikido says how the attacker got publishing access isn't known yet.

For agents built on cloud identities, the build runner is now the target: pin with hashes and restrict CI egress.

**Affected:** `agent-framework` 1.26.1 and 1.26.2, including installs made through loose requirements such as `agent-framework>=1.26` on 17 November · **Fixed in:** no patched release; 1.26.0 is the last clean version · **Severity:** Aikido rates it 100/100 critical; no CVE assigned · **Stopgap:** pin `agent-framework==1.26.0` and rebuild; block webhook.site egress if it isn't expected · **If compromised:** rotate every reachable secret, including Azure DevOps PATs and service connections, Azure service principals, and GitHub, npm, PyPI and Hugging Face tokens; removing the package doesn't undo data already sent, and don't launch Python or pip in an affected environment, since the payload runs on every start; rebuild from a clean image

[Source](https://www.aikido.dev/blog/two-malicious-agent-framework-releases-hit-pypi-in-33-minutes) · [Endor Labs](https://www.endorlabs.com/learn/agent-framework-compromised-software-supply-chain-attack)
